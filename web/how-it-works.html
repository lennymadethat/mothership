01What it is

A command deck for always-on machines.

Mothership is a mobile-first web app that remote-controls the computers in your fleet — your build server, your laptop, and every future machine. It runs Claude Code sessions as chat threads, opens a real terminal, streams live system stats, browses files, manages processes, and can lock, restart, or shut a machine down — all from a phone on the couch or a browser across the world.

It is not a remote desktop. Parsec streams pixels when you need to see the actual screen. Mothership is a purpose-built control surface for the thing that actually happens twenty times a day: kicking off, steering, and reviewing Claude Code work.

02No open ports — the relay

The whole trick, in one picture.

Traditional remote access pokes a hole in your machine: a port forward, a VPN, a tunnel daemon. Mothership never opens a single inbound port. Instead, a small Node agent — the bridge — runs on each machine and dials out to the hub, a Cloudflare Worker, over a WebSocket. Your phone connects to the same hub. A per-machine Durable Object sits in the middle and relays messages both ways.

The machine is invisible to the internet. There is nothing to scan, nothing to brute-force. If the bridge process dies, a supervised scheduled task respawns it within seconds; when the machine reboots, it comes back on its own.

Honest security note: the hub currently runs in open mode — the URL is the gate. Token auth is built in and the arming sequence is staged: a token is already generated and pre-loaded into the bridge; once every client carries it (paste it in Settings → Hub token on each device), setting one Worker secret enforces it with zero downtime. Until then, treat the URL like a password. Power actions (restart, shutdown) always double-confirm.

03Claude sessions as chat

Type anywhere. Queue like a pro. Hear the recap.

Every session is a persistent chat thread bound to a working folder on the machine. Messages run Claude Code headlessly on the machine itself — the same Claude, the same tools, the same repos as sitting at the keyboard. Replies stream back token by token, with every tool call chipped onto the message and the run's cost and duration stamped underneath.

Queueing: keep typing while Claude works. Extra messages stack with a ⏳ and feed the very next run with full context — exactly like queued messages in the Claude Code CLI.

Spoken recaps: after each reply, a second, tiny model pass boils the essay down to one or two spoken sentences. Tap 🔊 and the phone reads you the outcome — never the whole thing. Drafts survive navigation; attachments upload from the phone straight onto the machine.

04One hub, every machine

The fleet view from orbit.

Machines self-register the moment their bridge connects, with a green dot driven by a heartbeat. Switch machines in two taps. The Pro Desk turns the sessions list into a full-width trading-desk grid — four or five live Claude feeds side by side, each with its own status banner (running pulse, model, billing source, working folder, last reply) and its own composer.

05Browser control — the last gap, closed

Phone sessions can now drive a real Chrome on the machine.

Desk sessions get browser control from the Claude-in-Chrome extension — which, by Anthropic's design, only pairs with an interactive terminal. Headless Mothership sessions could never use it. So they get their own lane instead: every bridge-spawned session now loads Playwright MCP and Chrome DevTools MCP, driving the machine's installed Chrome — navigate, click, fill forms, screenshot, read consoles and network traffic — from a prompt typed on your phone.

Honest nuance: this is a fresh, automation-owned Chrome, not your logged-in day-to-day profile. For sites that need your logins, the roadmap move is a dedicated persistent profile that stays signed in for the automation lane.

06Standing orders

The phone stops being a remote and becomes an operator.

A standing order is a prompt with a clock: “07:30, weekdays — run the morning fleet check and summarize in ten lines.” The bridge fires it on the machine even with the app closed; the run flows through the normal pipeline, so the push notification and the spoken recap arrive like any other reply. Set them up in Settings → Standing orders.

08Under the hood

Three small parts, deliberately boring technology.

PartWhat it isWhy it's built that way
HubCloudflare Worker + one Durable Object per machine, KV registry, VAPID pushHibernating WebSockets cost nothing while idle; the DO relays browser ↔ bridge with no server to maintain
Web appVanilla no-build PWA — hash router, vendored xterm & marked, service workerNo framework, no bundler: any future Claude session can edit any file directly
BridgeNode agent per machine: claude -p --output-format stream-json, ConPTY terminal, stats, files, powerOutbound-only WebSocket; supervised scheduled task survives crashes and reboots

Session transcripts, queue state, and Claude's own conversation history all live on the machine — the hub stores nothing but a machine registry and notifications. Lose the hub and you lose nothing but the door.

09Mothership vs Parsec

They coexist on the same machines. Parsec streams the full desktop — pixels, GPU, trading screens, anything you can see. Mothership is lighter and sharper: it installs to the home screen, works over any connection, pushes a notification when the build lands, and reads you the recap out loud. Rule of thumb: kick off and steer work from your pocket → Mothership; need to see and touch the real screen → Parsec.
